# Flinch rebuild: end-to-end flows

Draft 1, 2026-10-16. Fifteen flows across the 30 screen specs in `screens/`. Each step names the screen (its spec file), the region (R-number from that spec), the control, the API call, what the researcher sees next, and the cue that answers "what now" for someone who has never used Flinch (a Readout sentence, a FirstTimeTip id, a disabled-reason string or an EmptyState). Visible strings are quoted from the specs and are drafts (draft; brad-voice pass). Where a step depends on a finding in `06-consistency-report.md`, the step cites it (F-number); the flow is written the way the finding's fix resolves it.

Conventions: "→" in the Sees-next column means navigation; a route in backticks is the hash route the step ends on; "tip" means a FirstTimeTip from the spec's §7, shown once. Every flow ends with the acceptance walk a tester runs in order; a walk step that names a spec check ("workbench §11.7") is that spec's numbered acceptance check.
